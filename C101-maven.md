## Explanation


*Apache Maven* is a **build tool** and **dependency manager** for Java projects. Without a build tool you would have to compile your sources by hand, download every library (`.jar` file) yourself, and add them to the classpath one by one. Maven automates all of these steps based on a single description file: the `pom.xml` (*Project Object Model*).

### Why do we need it?

1. Every Maven project has the **same directory layout**, so any developer (and any IDE) can find the sources, resources and tests immediately.
1. **Libraries are declared, not downloaded manually**: you write down what you need (and which version), Maven fetches it, together with everything that library depends on (*transitive dependencies*).
1. The build can be repeated on any machine with the same result, because the settings (Java version, encoding, dependencies) are stored in the project itself.

### The standard directory layout

```
project
├── pom.xml                  the description of the project
└── src
    ├── main
    │   ├── java             the source code of the application
    │   └── resources        non-code files (e.g. JSON documents) packaged with the application
    └── test
        └── java             the source code of the tests
```

The `target` folder is generated by the build (compiled classes, packages). It can be deleted at any time and should never be committed to the repository.

### The `pom.xml`

```xml
<groupId>org.example</groupId>      <!-- who owns the project (like a reversed domain name) -->
<artifactId>c1</artifactId>         <!-- the name of the project -->
<version>1.0-SNAPSHOT</version>     <!-- the version; SNAPSHOT means work in progress -->
```

The three elements together (the *coordinates*) identify an artifact uniquely. The same coordinates are used to refer to the libraries you depend on.

The `properties` element contains the settings of the build:

1. `maven.compiler.release`: the Java language level used for compiling (e.g. `25`)
1. `project.build.sourceEncoding`: the encoding of the source files (use `UTF-8`, otherwise accented characters may break on some machines)

### How does a dependency get to your project?

1. You add a `dependency` element (`groupId`, `artifactId`, `version`) to the `dependencies` element.
1. Maven looks for the artifact in the **local repository** (the `.m2` folder in your home directory).
1. If it is not there, Maven downloads it from the **Maven Central** repository and stores it locally, so the next build does not need the network.
1. The jar (and its own dependencies) are put on the classpath of your project.

The `scope` element controls *where* the dependency is used. The default is `compile` (everywhere, also at runtime). The value `provided` means that the library is needed only to compile the code, and it is not needed at runtime (this is the right choice for *Lombok*, see [`C102`](C102-lombok.md)).

> Tip: if you add a dependency in IDEA, do not forget to reload the Maven project (the small *m* icon that appears in the editor). Until you do, the new classes are not visible.
